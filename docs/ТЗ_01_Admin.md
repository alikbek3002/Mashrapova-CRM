## 2. Клиенты

### 2.1 Семейная карточка
- ФИО отца и матери, телефоны (формат `+996 XXX XXX XXX`).
- Ответственный менеджер (FK на `profiles`).
- Свободные комментарии.
- Один аккаунт = вся семья с несколькими детьми.

### 2.2 Карточка ребёнка
- Фото (приватный Storage, signed URL TTL 1 ч).
- ФИО, дата рождения, номер именной карты.
- Цветовой статус: `active` зелёный · `frozen` синий · `expired` серый · `debtor` красный · `archived`.

**Вкладки в карточке:**
- **Абонементы** — все карты с историей (тип, остаток, заморозки, период).
- **Посещения** — список занятий по датам со статусами.
- **Платежи** — журнал оплат + LTV.
- **Заморозки** — история (дата, причина, инициатор, статус).
- **Успехи** — `progress_notes` от тренеров.
- **Комментарии** — внутренние заметки менеджера (не видны родителю).

### 2.3 Поиск
- По ФИО ребёнка, ФИО родителя, телефону, номеру карты.
- Debounce 200ms, ответ < 300ms.
- Postgres trigram-индекс на `children.full_name`, `families.father_name`, `families.mother_name`.

### 2.4 Создание карточек
- Форма «Новый ребёнок»: имя, дата рождения, фото, привязка к семье (или создание новой).
- Форма «Новая семья» с валидацией zod.
- Несколько детей у одной семьи.

## 3. Тренеры

### 3.1 Карточка тренера
- Фото, ФИО, описание, достижения, телефон.
- Статус: `active` / `archived`.
- Список секций тренера, расписание по группам (read-only, создаётся в «Расписании»).

### 3.2 Создание
- Форма создания нового тренера + привязка к секциям (m2m через `section_coaches`).
- При создании автоматически генерится `auth.users` и magic link отправляется на email.

---

## 4. Секции и группы

### 4.1 Карточка секции
- Название (ru + ky), направление: `gymnastics` / `martial_arts` / `special`.
- Тренер (если несколько — основной).
- Стоимость абонемента и стоимость пробного занятия — в каждой секции отдельно.

### 4.2 Группа
- Название, секция, тренер, дни и время (через `group_schedule`), длительность (мин).
- **Жёсткий лимит** детей с возможностью ручного переопределения (`hard_limit_override = true`).
- Состав группы — список enrollments.

---

## 5. Расписание

### 5.1 Виды
- **Недельный** — сетка по дням с цветной меткой по секции; клик на занятие → drawer со списком детей.
- **Месячный** — обзор всех занятий месяца (компактный mode).

### 5.2 Создание занятия
Форма: секция → тренер → дата/время → лимит участников → тип (`regular` / `trial` / `single`).

**Валидация (бэкенд):**
- Конфликт тренера по времени → 409 + текст ошибки.
- Лимит по группе превышен → блокировка с предупреждением.

### 5.3 Редактирование
- **Перенос** — изменение даты/времени.
- **Отмена** — `lessons.status = 'cancelled'`. Если флаг `force_majeure = true`, бэкенд автоматически добавляет +1 занятие к балансу всех записанных детей (через создание записей `freezes` со статусом `approved` и причиной «force_majeure»).

## 6. Абонементы и клубные карты

### 6.1 Типы карт

| Тип | Занятий | Заморозки |
|---|---|---|
| Месячный | 12 | 0 |
| Трёхмесячный | 36 | 3 |
| Персональный | по договору | по договору |
| Разовый | 1 | 0 |
| Пробный | 1 | 0 |

### 6.2 Продажа
1. Выбор клиента (или создание новой семьи + ребёнка)
2. Выбор секции и типа карты
3. Применение скидки (500 сом на 2-го ребёнка из семьи — автоматом; индивидуальная — вручную)
4. Фиксация оплаты (cash/terminal)
5. Активация карты

Транзакция **на бэке** (`POST /v1/cards/sell`):
- Создаёт `club_cards` + `payments` + запись в `audit_log`.
- Идемпотентность по `idempotency_key`.

### 6.3 Остаток занятий
- Считается через VIEW `v_child_card_balance`: `total_lessons − attended_present + approved_freezes`.
- Отображается в карточке ребёнка крупно.

### 6.4 Статусы карты
- `active` — есть остаток, дата окончания > сегодня
- `ending` — остаётся ≤ 5 дней или ≤ 2 занятий (триггер на дашборд обзвона)
- `frozen` — заморозка активна
- `expired` — дата прошла
- `debt` — посещает без оплаты следующего периода
- `archived`

### 6.5 Скидки
- **500 сом** фиксированная на 2-го ребёнка из семьи — авто.
- Индивидуальные — вручную менеджером, с указанием причины (audit log).

## 7. Заморозки

### 7.1 Источники
- **От тренера** — тренер инициирует через свой PWA → `freezes.status = 'pending'` → пуш-уведомление в admin (через `notifications` таблицу) → менеджер подтверждает или отклоняет.
- **От менеджера** — карточка ребёнка → «Заморозить» → причина → сразу `approved`.
- **Форс-мажор** — отмена занятия с флагом → батч `approved`-фризов всем enrollments (одна транзакция на бэке).

### 7.2 История
В карточке ребёнка во вкладке «Заморозки»: дата, причина, инициатор (роль + имя), статус.

---

## 8. Платежи

### 8.1 Фиксация
Ручной ввод: сумма, дата, метод (`cash` / `terminal`), кто принял, комментарий.

Только через бэкенд (`POST /v1/payments`) с `idempotency_key`.

### 8.2 Журнал
- Список всех оплат по ребёнку.
- **LTV** ребёнка (sum payments).
- Фильтры: по дате, методу, кассиру.

---

## 9. Дашборды

### 9.1 Дашборд директора (главная)
KPI сверху:
- Активных детей
- Выручка за месяц
- Активных абонементов
- Заканчивающихся 7-дневных
- Загрузка по секциям (% от лимита)

Ниже:
- Расписание сегодня
- Виджет последних регистраций
- График посещаемости 30 дней

Источник данных: VIEW `v_director_kpi` + точечные запросы.

### 9.2 Дашборд обзвона
- Список детей, чьи карты истекают в ближайшие 5 дней (статус `ending`).
- Колонки: ребёнок, секция, дата окончания, телефон родителя, ответственный менеджер.
- Чекбоксы: `service_call_done`, `whatsapp_sent` (хранятся в `crm_actions` или прямо в `club_cards`).
- Блок **должники** — карты со статусом `debt`.

## 13. Критерии приёмки админ-панели

1. Менеджер логинится через email → magic link
2. Создаёт семью + двух детей, видит автоматическую скидку 500 сом на втором абонементе
3. Продаёт абонемент с фиксацией платежа — запись появляется в audit_log
4. В расписании видит конфликт тренера при попытке создать занятие в занятое время
5. Подтверждает заморозку от тренера — баланс ребёнка пересчитывается
6. На дашборде обзвона видит список истекающих карт за 5 дней
7. Все суммы — в `numeric(12,2)`, никаких float-артефактов
