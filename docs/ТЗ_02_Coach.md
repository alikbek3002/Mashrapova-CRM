# ТЗ 02 · PWA тренера — Uniqum Sport ERP

> Общие требования (стек, БД, безопасность, инфраструктура): [ТЗ 00](ТЗ_00_Общие_требования.md)
> Связанные продукты: [Админ-панель](ТЗ_01_Admin.md) · [PWA родителя](ТЗ_03_Parent.md)

**Целевая платформа:** телефон / планшет, мобильный браузер.
**Установка:** PWA (manifest + SW), без захода в магазин.
**Авторизация:** email + magic link (как у менеджера).
**Видимость:** только свои группы и свои дети (через RLS).

---

## 1. Принцип «минимум полей видимости»

Тренер **видит**:
- Свои группы и enrollments
- Карточки детей из своих групп (имя, фото, возраст, остаток занятий по карте, контакты родителей)
- Расписание своих занятий
- Свои `progress_notes`

Тренер **НЕ видит**:
- Финансы клиента, LTV, платежи
- Чужие группы и чужих детей
- Настройки системы, цены, скидки
- Карточки родителей напрямую (только телефон родителей в карточке ребёнка)

RLS-политики реализуют это на уровне БД — даже при ошибке во фронте утечки не будет.

## 2. Экраны

### 2.1 🏠 Сегодня (главный экран)
- Приветствие: «Добрый день, [Имя]».
- Список сегодняшних занятий тренера:
  - Время начала и длительность
  - Название группы (секция · группа)
  - Число записанных детей
  - Кнопка «Открыть журнал»
- Быстрая ссылка на табель месяца.

### 2.2 ✅ Журнал посещений
Открывается из «Сегодня» или из списка групп.

- Заголовок: группа + дата + время.
- Список детей (отсортирован по имени).
- **По умолчанию все дети «пришли»** — это снижает рутину (тренер тапает только тех, кого нет).
- Тап по ребёнку → быстрая смена статуса:
  - `present` (пришёл) — зелёный
  - `absent` (не пришёл) — красный
  - `excused` (уважительная) — жёлтый
  - `late` (опоздал) — оранжевый
  - `makeup` (отработка) — синий
- Оптимистичные апдейты: UI меняется мгновенно, запись в БД асинхронно. При ошибке — toast и откат.
- Кнопка «Сохранить» закрывает занятие (но автосейв на каждый тап тоже работает).

**Эндпоинт:** запись напрямую в Supabase через RLS (coach пишет только в `attendance` своих групп).

### 2.3 📅 Табель месяца
- Группа → сетка «дети × даты» за календарный месяц.
- Цветные точки — как в Google Sheets:
  - 🟢 present
  - 🔴 absent
  - 🟡 excused
  - 🟠 late
  - 🔵 makeup
- Можно редактировать **только последние 7 дней** (защита от ошибок).
- Скролл по горизонтали для длинных месяцев.

### 2.4 🧒 Карточка ребёнка
Открывается тапом на имя в журнале / табеле.

Видит:
- Имя, фото, дата рождения
- Активный абонемент: тип, остаток занятий, дата окончания
- Статус заморозки (если есть)
- История посещений за последние 90 дней
- Контакты родителей (имя + кнопка позвонить + кнопка WhatsApp)
- Свои `progress_notes` об этом ребёнке

НЕ видит: платежи, LTV, цену абонемента, финансовые комментарии менеджера.

### 2.5 📝 Заметки о прогрессе
- В карточке ребёнка кнопка «Добавить заметку».
- Поле текста (до 500 символов).
- Чекбокс «Показать родителю» (по умолчанию включен).
- При сохранении — заметка моментально появляется в **PWA родителя** (если is_public).

### 2.6 ❄️ Заморозка
- Из карточки ребёнка → «Заморозить занятие».
- Поля: причина (выпадающий список + поле для своего варианта).
- Сохранение → `freezes.status = 'pending'`, `initiator_role = 'coach'`.
- Менеджер получает уведомление в админке (`notifications` таблица).
- В UI тренера отображается «На рассмотрении менеджера».

### 2.7 👥 Мои группы
- Полный список групп тренера.
- В каждой: название, секция, количество детей, расписание.
- Тап → состав группы (список enrollments).

## 3. UX-правила для тренера

### 3.1 Крупные тач-таргеты
Все интерактивные элементы — минимум **44 × 44 px**. Тренер работает в зале, может быть мокрыми руками или в перчатках.

### 3.2 Работа в плохой связи
- Оптимистичные апдейты на всех тапах статуса.
- Локальная очередь несинхронизированных изменений (через React Query mutation cache).
- При восстановлении сети — авто-ретрай.

### 3.3 Минимум модалок
Все основные действия — inline на экране. Модалки только для подтверждения деструктивных действий (например, удаление заметки).

## 4. Технические детали

### 4.1 Существующий файл
- [frontend/src/CoachScreen.tsx](../frontend/src/CoachScreen.tsx) — UI готов на mock-данных, требует разделения на экраны и подключения к Supabase.

### 4.2 Маршруты внутри PWA тренера
```
/coach              → Сегодня (default)
/coach/today        → Сегодня
/coach/lesson/:id   → Журнал посещений
/coach/tabel/:groupId → Табель месяца
/coach/child/:id    → Карточка ребёнка
/coach/groups       → Мои группы
```

### 4.3 PWA-манифест (отдельный от родителя)
```json
{
  "name": "Uniqum Тренер",
  "short_name": "Coach",
  "start_url": "/coach",
  "scope": "/coach/",
  "display": "standalone",
  "theme_color": "#2563eb",
  "icons": [...]
}
```

### 4.4 Запросы в Supabase
- `useTodayLessons()` — `lessons.coach_id = me AND date = today`
- `useGroupAttendance(groupId, month)` — табель
- `useChildProfile(childId)` — карточка с RLS check
- `useUpsertAttendance()` — оптимистичная мутация

### 4.5 Действия только через бэкенд
- Создание заморозки тренером → `POST /v1/freezes` (бэк проверяет, что coach действительно ведёт эту группу).

## 5. Критерии приёмки PWA тренера

1. Тренер открывает ссылку → видит приветствие + сегодняшние занятия
2. Тапает «Открыть журнал» → видит список детей с предзаполненным `present`
3. Тапает на ребёнка, который не пришёл → статус меняется на `absent` за < 100ms
4. При выключенном Wi-Fi изменения не теряются — синхронизируются после восстановления
5. Открывает карточку ребёнка → видит остаток занятий, не видит финансы
6. Создаёт `progress_note` с галкой «Показать родителю» → родитель видит её через 30 секунд после refresh
7. Инициирует заморозку → менеджер видит уведомление в админке
8. Попытка SQL-инъекции в `progress_note.text` → текст экранируется при выводе (React + Supabase parametrized queries)
