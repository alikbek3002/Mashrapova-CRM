# ТЗ 03 · PWA родителя — Uniqum Sport ERP

> Общие требования (стек, БД, безопасность, инфраструктура): [ТЗ 00](ТЗ_00_Общие_требования.md)
> Связанные продукты: [Админ-панель](ТЗ_01_Admin.md) · [PWA тренера](ТЗ_02_Coach.md)

**Целевая платформа:** телефон, мобильный браузер.
**Установка:** PWA (manifest + SW), без захода в магазин.
**Открытие:** по ссылке из WhatsApp.
**Авторизация:** phone OTP (через Supabase Auth + WhatsApp/SMS).
**Один аккаунт = вся семья:** свитчер между детьми.

---

## 1. Принцип «read-only для родителя в Фазе 1»

Родитель **видит**:
- Своих детей (через `families.parent_user_id = auth.uid()`)
- Расписание, посещения, абонемент каждого ребёнка
- Публичные `progress_notes` тренеров
- Свои платежи

Родитель **НЕ может в Фазе 1**:
- Самостоятельно записать ребёнка в секцию (Фаза 2)
- Оплатить абонемент онлайн (Фаза 2 — MBank)
- Чатиться с тренером (Фаза 2)

RLS-политики реализуют это на уровне БД: даже при ошибке во фронте утечки не будет.

## 2. Экраны

### 2.1 👶 Мои дети (свитчер)
- Свитчер между детьми семьи в верхней части экрана.
- Аватарки + имена.
- Если ребёнок один — свитчер скрыт автоматически.
- Активный ребёнок выделен.
- При смене ребёнка — все экраны ниже обновляются.

### 2.2 🏠 Обзор ребёнка (главный экран)
- Фото ребёнка (signed URL TTL 1 час)
- Имя
- Секция и имя тренера
- **Ближайшее занятие**: дата, время, тренер
- **Остаток занятий по абонементу — крупным шрифтом**
- Карточки с быстрым переходом: Расписание · Посещения · Абонемент

### 2.3 📅 Расписание
- Неделя вперёд.
- Каждое занятие:
  - Дата, день недели
  - Время начала, длительность
  - Секция, имя тренера
  - Цветовая метка по секции (из `sections.color` или хеша id)
- Если занятие отменено — пометка «Отменено» серым.

### 2.4 ✅ Посещения
- Календарь с цветными точками за текущий месяц:
  - 🟢 present — был
  - 🔴 absent — не был
  - 🟡 excused — уважительная
  - 🔵 makeup — отработка
- Список под календарём по датам со статусом.
- Возможность пролистать предыдущие месяцы.

### 2.5 🎫 Абонемент
- **Текущий абонемент:**
  - Название (Месячный · 12 занятий и т.п.)
  - Остаток занятий
  - Дата окончания
  - Прогресс-бар «использовано из X»
- **История абонементов** — все предыдущие карты ребёнка.
- **История заморозок** — даты и причины (без финансовых деталей).

### 2.6 ⭐ Заметки тренера
- Только публичные заметки (`progress_notes.is_public = true`).
- Хронологический порядок (сверху самые новые).
- Заголовок каждой: дата + имя тренера.
- Возможность поделиться (Web Share API).

### 2.7 💰 История платежей
- Список:
  - Дата
  - Сумма (формат `1 500 сом`)
  - Метод (наличные / терминал)
  - За что (тип карты, период)
- Без LTV, без скидок (это внутренняя информация центра).

### 2.8 📞 Связь с клубом
- **Кнопка «WhatsApp менеджеру»** — `https://wa.me/<phone>` deep link
  - Если у семьи назначен ответственный менеджер — пишет ему лично.
  - Иначе — общий контакт центра.
- **Кнопка «Позвонить в клуб»** — `tel:<phone>` link.

## 3. UX-правила для родителя

### 3.1 Простота
Родитель — нетехнический пользователь. Минимум вкладок, никакой формальной терминологии. «Абонемент», а не «Клубная карта». «Занятий осталось», а не «Баланс».

### 3.2 Скорость
- Загрузка обзорного экрана < 1 сек на 3G.
- Скелетоны вместо спиннеров.
- Все запросы кэшируются React Query на 5 минут.

### 3.3 Доступность
- Контрастность WCAG AA.
- Шрифт от 16px (родители разных возрастов).
- Цветные индикаторы дублируются иконкой/текстом (для дальтоников).

## 4. Технические детали

### 4.1 Существующий файл
- [frontend/src/ParentScreen.tsx](../frontend/src/ParentScreen.tsx) — UI готов на mock-данных, требует разделения на экраны и подключения к Supabase.

### 4.2 Маршруты внутри PWA родителя
```
/parent                  → Обзор активного ребёнка (default)
/parent/schedule         → Расписание
/parent/attendance       → Посещения
/parent/card             → Абонемент
/parent/notes            → Заметки тренера
/parent/payments         → Платежи
```

### 4.3 PWA-манифест (отдельный от тренера)
```json
{
  "name": "Uniqum Родитель",
  "short_name": "Uniqum",
  "start_url": "/parent",
  "scope": "/parent/",
  "display": "standalone",
  "theme_color": "#eab308",
  "icons": [...]
}
```

### 4.4 Запросы в Supabase
- `useMyChildren()` — `families.parent_user_id = auth.uid()` → children
- `useChildOverview(childId)` — карточка ребёнка с активной картой
- `useChildSchedule(childId, range)` — будущие занятия
- `useChildAttendance(childId, month)` — точки календаря
- `useChildNotes(childId)` — `is_public = true` only
- `useChildPayments(childId)` — `payments` с RLS check

Все запросы фильтруются по RLS: родитель не сможет получить чужие данные даже подменив `childId`.

### 4.5 Аутентификация phone OTP
1. Родитель открывает ссылку из WhatsApp → попадает на экран «Введите телефон».
2. Вводит телефон → Supabase отправляет OTP в WhatsApp/SMS.
3. Вводит код → получает JWT.
4. Сессия хранится в localStorage с auto-refresh.
5. Если устройство «забыло» сессию — повторный OTP.

## 5. Безопасность специфичная для родителя

- Никаких финансовых деталей кроме своих платежей.
- Фото ребёнка — приватный bucket, signed URL короткого TTL.
- При смене телефона у родителя — менеджер вручную обновляет `families.parent_user_id` (защита от перехвата чужого аккаунта).
- Rate limit на phone OTP — 3 попытки на номер в 5 минут.
- При вводе неверного OTP 5 раз → блокировка номера на час.

---

## 6. Критерии приёмки PWA родителя

1. Родитель открывает WhatsApp ссылку → попадает на экран ввода телефона
2. Вводит свой телефон → получает OTP в WhatsApp → авторизуется
3. Видит свитчер с двумя детьми (если в семье двое)
4. Переключает ребёнка → весь UI обновляется
5. Видит ближайшее занятие и остаток крупным шрифтом
6. Открывает заметку тренера, добавленную час назад
7. Тапает «WhatsApp менеджеру» → открывается чат с ответственным менеджером
8. Попытка зайти под чужим аккаунтом (подмена JWT) → видит только своих детей (RLS блокирует)
9. Установка PWA на главный экран iOS/Android работает
